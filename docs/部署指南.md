## 前置要求

### 必需工具

**1. AWS CLI (v2.x 或更高版本)**
```bash
aws --version
```
安装指南: https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html

**2. Python 3.11+**
```bash
python3 --version
```

**3. Git**
```bash
git --version
```

**4. Docker** (用于ECS部署)
```bash
docker --version
```

### AWS账户要求

- 有效的AWS账户
- IAM用户或角色，需要以下权限：
  - EC2 (完全访问)
  - S3 (完全访问)
  - DynamoDB (完全访问)
  - CloudFormation (完全访问)
  - IAM (创建角色和策略)
  - Bedrock (调用模型和管理Knowledge Base)
  - CloudWatch (日志和指标)
  - Secrets Manager (创建和读取密钥)
  - EventBridge (创建规则)
  - Lambda (创建和调用函数)

**Bedrock访问权限**：
1. 登录AWS控制台 → Bedrock → Model access
2. 申请访问 Claude 3.5 Sonnet 模型
3. 等待审批（通常立即通过）

### 创建EC2密钥对

```bash
aws ec2 create-key-pair \
  --key-name aws-pricing-assistant-key \
  --query 'KeyMaterial' \
  --output text > ~/.ssh/aws-pricing-assistant-key.pem

chmod 400 ~/.ssh/aws-pricing-assistant-key.pem
```

## 快速开始

完整自动化部署：

```bash
# 1. 克隆代码仓库
git clone <repository-url>
cd aws-pricing-assistant

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env 文件，填入您的配置

# 3. 配置AWS凭证
aws configure

# 4. 执行完整部署
export AWS_REGION=us-east-1
export KEY_PAIR_NAME=aws-pricing-assistant-key
./scripts/deploy_all.sh
```

这将部署：
- 完整的AWS基础设施（VPC、ALB、EC2、S3等）
- DynamoDB表
- Bedrock Knowledge Base
- EventBridge爬虫定时任务
- 后端应用
- 前端应用

**预计时间**: 30-40分钟

## 详细部署步骤

### 步骤1: 部署基础设施

使用CloudFormation部署完整的AWS基础设施：

```bash
# 设置环境变量
export AWS_REGION=us-east-1
export STACK_NAME=aws-pricing-assistant
export ENVIRONMENT=production
export INSTANCE_TYPE=t3.medium
export KEY_PAIR_NAME=aws-pricing-assistant-key

# 可选：自定义域名
export DOMAIN_NAME=pricing.example.com
export CERTIFICATE_ARN=arn:aws:acm:us-east-1:123456789012:certificate/xxx

# 部署基础设施
./scripts/deploy_infrastructure.sh
```

**创建的资源**：
- VPC（2个公有子网，跨2个可用区）
- Application Load Balancer + 目标组
- Auto Scaling Group（1-4个EC2实例）
- 3个S3存储桶（前端、报价、知识库）
- CloudFront分发
- IAM角色和安全组
- CloudWatch日志组
- Secrets Manager密钥

**预计时间**: 10-15分钟

### 步骤2: 创建DynamoDB表

创建所有必需的DynamoDB表：

```bash
./scripts/setup_dynamodb.sh
```

**创建的表**：
- `aws-pricing-assistant-users` (用户表，带username索引)
- `aws-pricing-assistant-sessions` (会话表，带TTL)
- `aws-pricing-assistant-quotes` (报价表，带user-quotes索引)
- `aws-pricing-assistant-cloud-services` (云服务表，带category和date索引)
- `aws-pricing-assistant-mapping-cache` (映射缓存表，带TTL)

**预计时间**: 2-3分钟

### 步骤3: 设置Bedrock Knowledge Base

设置用于服务映射和定价数据的Knowledge Base：

```bash
# 上传知识库数据到S3
python3 scripts/setup_knowledge_base_s3.py

# 创建Bedrock Knowledge Base
python3 scripts/create_bedrock_knowledge_base.py
```

**注意**: 创建完成后，更新 `.env` 文件中的Knowledge Base ID：
```bash
BEDROCK_KNOWLEDGE_BASE_ID=<your-kb-id>
```

**预计时间**: 5-10分钟

### 步骤4: 配置EventBridge爬虫定时任务

配置每日自动爬虫任务：

```bash
# 默认：每天UTC时间凌晨2点执行
./scripts/setup_eventbridge_crawler.sh

# 自定义时间表
export SCHEDULE_EXPRESSION="cron(0 3 * * ? *)"  # UTC时间凌晨3点
./scripts/setup_eventbridge_crawler.sh
```

**创建的资源**：
- Lambda函数（Web爬虫）
- EventBridge规则（每日执行）
- IAM角色（必要权限）

**预计时间**: 3-5分钟

### 步骤5: 部署后端应用

部署FastAPI后端应用：

#### 选项A: EC2部署

```bash
export DEPLOYMENT_TYPE=ec2
export EC2_INSTANCE_ID=<从CloudFormation输出获取>
./scripts/deploy_backend.sh
```

#### 选项B: ECS部署

```bash
export DEPLOYMENT_TYPE=ecs
export ECS_CLUSTER=aws-pricing-assistant-cluster
./scripts/deploy_backend.sh
```

**预计时间**: 5-10分钟

### 步骤6: 部署前端应用

将Web界面部署到S3和CloudFront：

```bash
# 从基础设施堆栈获取后端URL
export BACKEND_API_URL=<从CloudFormation输出获取ALB URL>
export S3_BUCKET=<从CloudFormation输出获取前端存储桶>
export CLOUDFRONT_ENABLED=true

./scripts/deploy_frontend.sh
```

**预计时间**: 3-5分钟（CloudFront分发需额外15-20分钟）

### 步骤7: 配置CloudWatch日志

配置CloudWatch日志组和监控：

```bash
python3 scripts/setup_cloudwatch_logs.py
```

**预计时间**: 1-2分钟

### 步骤8: 验证部署

验证部署是否成功：

```bash
# 运行验证脚本
python3 verify_setup.py

# 测试后端API
curl http://<alb-url>/health

# 测试前端
curl http://<cloudfront-url>
```

## 配置说明

### 环境变量配置

编辑 `.env` 文件：

```bash
# AWS配置
AWS_REGION=us-east-1
AWS_ACCOUNT_ID=123456789012

# Bedrock配置
BEDROCK_MODEL_ID=anthropic.claude-3-5-sonnet-20241022-v2:0
BEDROCK_KNOWLEDGE_BASE_ID=<your-kb-id>

# DynamoDB表名
DYNAMODB_USERS_TABLE=aws-pricing-assistant-users
DYNAMODB_SESSIONS_TABLE=aws-pricing-assistant-sessions
DYNAMODB_QUOTES_TABLE=aws-pricing-assistant-quotes
DYNAMODB_CLOUD_SERVICES_TABLE=aws-pricing-assistant-cloud-services
DYNAMODB_MAPPING_CACHE_TABLE=aws-pricing-assistant-mapping-cache

# S3存储桶
FRONTEND_BUCKET=<frontend-bucket-name>
QUOTE_BUCKET=<quote-bucket-name>
KNOWLEDGE_BASE_BUCKET=<kb-bucket-name>

# 认证配置
JWT_SECRET_KEY=<生成安全随机字符串>
JWT_ALGORITHM=HS256
JWT_EXPIRATION_MINUTES=30

# API配置
API_HOST=0.0.0.0
API_PORT=8000
API_WORKERS=4

# 日志配置
LOG_LEVEL=INFO
CLOUDWATCH_LOG_GROUP=/aws/pricing-assistant/production

# Web爬虫配置
CRAWLER_SCHEDULE=cron(0 2 * * ? *)
CRAWLER_TIMEOUT=900
```

### 生成安全密钥

```bash
# 生成JWT密钥
python3 -c "import secrets; print(secrets.token_urlsafe(32))"

# 生成加密密钥
python3 scripts/generate_encryption_key.py
```

### 更新Secrets Manager

```bash
aws secretsmanager update-secret \
  --secret-id aws-pricing-assistant-secrets \
  --secret-string '{
    "JWT_SECRET_KEY": "your-secure-random-string",
    "ENCRYPTION_KEY": "your-encryption-key"
  }'
```

## 常见问题

### 1. Bedrock访问被拒绝

**错误**: `AccessDeniedException: Could not access Bedrock`

**解决方案**:
- 进入AWS控制台 → Bedrock → Model access
- 申请访问Claude模型
- 等待审批通过

### 2. DynamoDB表已存在

**错误**: `ResourceInUseException: Table already exists`

**解决方案**:
- 表已存在，跳过创建步骤
- 或删除现有表后重新创建：
  ```bash
  aws dynamodb delete-table --table-name aws-pricing-assistant-users
  ```

### 3. 无法访问EC2实例

**错误**: 无法SSH到EC2实例

**解决方案**:
- 检查安全组是否允许SSH（端口22）
- 验证密钥对是否正确
- 确认实例在公有子网且有公网IP

### 4. 前端无法加载

**错误**: 前端显示空白页或错误

**解决方案**:
- 检查 `config.js` 中的后端URL是否正确
- 验证后端已启用CORS
- 确认CloudFront分发已部署完成
- 清除浏览器缓存

### 5. Knowledge Base未找到

**错误**: `ResourceNotFoundException: Knowledge Base not found`

**解决方案**:
- 验证 `.env` 中的Knowledge Base ID
- 确认Knowledge Base在正确的区域创建
- 确保S3存储桶有数据且可访问

## 维护指南

### 定期任务

#### 更新应用

```bash
# 拉取最新代码
git pull origin main

# 重新部署后端
./scripts/deploy_backend.sh

# 重新部署前端
./scripts/deploy_frontend.sh
```

#### 更新Knowledge Base

```bash
# 更新知识库数据
python3 scripts/setup_knowledge_base_s3.py

# 同步Knowledge Base
aws bedrock-agent start-ingestion-job \
  --knowledge-base-id <kb-id> \
  --data-source-id <data-source-id>
```

#### 监控爬虫

```bash
# 查看爬虫执行历史
aws events list-rule-names-by-target \
  --target-arn <lambda-arn>

# 查看最近的爬虫运行
aws lambda list-invocations \
  --function-name aws-pricing-assistant-crawler
```

#### 数据库维护

```bash
# 备份DynamoDB表
aws dynamodb create-backup \
  --table-name aws-pricing-assistant-users \
  --backup-name users-backup-$(date +%Y%m%d)

# 查看表指标
aws dynamodb describe-table \
  --table-name aws-pricing-assistant-users
```

### 扩展配置

#### 扩展EC2实例

```bash
# 更新Auto Scaling Group
aws autoscaling set-desired-capacity \
  --auto-scaling-group-name aws-pricing-assistant-asg \
  --desired-capacity 4
```

#### 扩展DynamoDB

```bash
# 更新表容量
aws dynamodb update-table \
  --table-name aws-pricing-assistant-users \
  --provisioned-throughput ReadCapacityUnits=10,WriteCapacityUnits=10
```

## 成本估算

基于中等使用量（每月1000个报价）：

| 服务 | 月成本（美元） |
|------|---------------|
| EC2 (2x t3.medium) | ~$60 |
| ALB | ~$20 |
| DynamoDB (按需) | ~$10 |
| S3 | ~$5 |
| CloudFront | ~$10 |
| Bedrock | ~$50 (根据使用量) |
| Lambda | ~$5 |
| CloudWatch | ~$5 |
| **总计** | **~$165/月** |

### 成本优化建议

1. **使用预留实例** - EC2可节省高达70%
2. **启用S3智能分层** - 自动优化存储成本
3. **使用DynamoDB按需模式** - 适合可变工作负载
4. **设置S3生命周期策略** - 自动删除旧报价
5. **监控Bedrock使用** - 优化提示词以减少调用
6. **使用CloudFront缓存** - 减少源站请求

## 安全最佳实践

### 部署前检查清单

- [ ] 更改所有默认密码和密钥
- [ ] 启用HTTPS并配置有效SSL证书
- [ ] 配置AWS WAF规则
- [ ] 设置CloudWatch告警
- [ ] 启用CloudTrail日志记录
- [ ] 审查并限制安全组规则
- [ ] 启用DynamoDB时间点恢复
- [ ] 配置S3存储桶生命周期策略
- [ ] 配置备份和灾难恢复
- [ ] 记录事件响应程序

### 网络安全

- ✅ 使用VPC和私有子网保护敏感资源
- ✅ 配置最小权限安全组
- ✅ 启用VPC Flow Logs
- ✅ 使用AWS WAF保护ALB

### 数据安全

- ✅ 为DynamoDB启用静态加密
- ✅ 启用S3存储桶加密
- ✅ 所有通信使用HTTPS/TLS
- ✅ 定期轮换加密密钥

### 访问控制

- ✅ 使用IAM角色而非访问密钥
- ✅ 为AWS控制台访问启用MFA
- ✅ 实施最小权限IAM策略
- ✅ 定期审计IAM权限

### 监控和日志

- ✅ 启用CloudTrail进行审计日志记录
- ✅ 为关键指标设置CloudWatch告警
- ✅ 监控应用程序日志中的错误
- ✅ 启用AWS Config进行合规性检查
